# VEDANTA Security and Threat Defense Architecture

## 1. Overview and Threat Model

As an institutional platform designed to crawl web domains, ingest uploaded or discovered PDF files, and serve student search queries, VEDANTA defends against multiple potential attack vectors:

1. **Server-Side Request Forgery (SSRF):** Malicious URLs redirecting crawler workers to internal subnet IPs, Docker containers, or cloud metadata services (`169.254.169.254`).
2. **Directory Traversal:** Malicious file paths attempting to overwrite or inspect server files outside the designated `data/` directory.
3. **Indirect Prompt Injection:** Unsanitized text in crawled web pages or PDFs attempting to hijack downstream synthesis.
4. **Denial of Service (DoS):** Uncontrolled crawling leading to IP banning or server resource exhaustion.
5. **SQL Injection:** Malicious inputs in search or admin endpoints.

---

## 2. SSRF Guard & URL Validation

All URL requests generated by the crawler or submitted by administrators must pass the `URLValidator` (`backend/app/ingestion/crawler/url_validator.py`):

```python
# Allowed Domain Whitelist
ALLOWED_DOMAINS = {
    "mitaoe.ac.in",
    "www.mitaoe.ac.in",
    "erp.mitaoe.ac.in"
}

# Forbidden IP Ranges (RFC 1918, RFC 3927, Loopback, Cloud Metadata)
PRIVATE_IP_NETWORKS = [
    ipaddress.ip_network("127.0.0.0/8"),       # Loopback
    ipaddress.ip_network("10.0.0.0/8"),        # Private network
    ipaddress.ip_network("172.16.0.0/12"),     # Private network
    ipaddress.ip_network("192.168.0.0/16"),    # Private network
    ipaddress.ip_network("169.254.0.0/16"),    # Link-local & Cloud Metadata
    ipaddress.ip_network("::1/128"),           # IPv6 loopback
    ipaddress.ip_network("fc00::/7"),          # IPv6 ULA
]
```

### Pre-Fetch DNS Resolution Defense
Before initiating any HTTP connection:
1. The domain name is resolved to its IP address using `socket.gethostbyname`.
2. The resolved IP is evaluated against `PRIVATE_IP_NETWORKS`.
3. If the IP falls into any private, loopback, or link-local range, the request is immediately aborted with a `SecurityViolationError`.
4. Only `http://` and `https://` protocols are permitted; `file://`, `ftp://`, or `gopher://` schemes are strictly rejected.

---

## 3. Polite Crawling and Rate Limiting

To maintain institutional compliance and avoid placing undue strain on MITAOE's web servers:
- **`robots.txt` Compliance:** The crawler parses `https://mitaoe.ac.in/robots.txt` before crawling any path, respecting `Disallow` directives and explicit crawl delays.
- **Configurable Inter-Request Delays:** Default delay of $1.0\text{ s}$ between requests to the same hostname.
- **Strict Concurrency Limits:** Crawl concurrency is capped at 5 asynchronous workers by default.
- **Identifiable User-Agent:**
  ```
  User-Agent: VEDANTA-Bot/1.0 (+https://mitaoe.ac.in; Institutional Research Crawler)
  ```

---

## 4. Path Traversal & File System Sandbox

All downloaded PDFs, extracted text chunks, and vector index files are restricted to the designated `data/` directory:
- Filenames derived from remote URLs are hashed using SHA-256 (`_file_hash`) to avoid directory traversal sequences like `../../etc/passwd` or `..\Windows\System32`.
- Canonical absolute paths are verified with `Path.resolve()` to ensure they remain inside `settings.DATA_DIR`.

---

## 5. Parameterized Queries & Input Validation

- **SQL Injection Defense:** All database interactions utilize SQLAlchemy 2.0 ORM with bind parameters. Raw string formatting or unescaped SQL queries are prohibited.
- **Input Sanitization:** User queries submitted via `/api/v1/search` are validated through Pydantic v2 schemas:
  - String length bounded to $\le 1000$ characters.
  - Non-printable and malicious control characters stripped.
  - Sub-queries bounded to a maximum of 5 splits to prevent computational exhaustion.

---

## 6. Prompt Injection Defense

Because VEDANTA uses deterministic search pipelines (BM25 + FAISS + Evidence Validation) rather than passing unconstrained user prompts directly to autonomous third-party LLMs with tool execution rights, prompt injection attacks in web content cannot execute unauthorized system commands or leak credentials.
